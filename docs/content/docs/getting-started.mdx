CerbIA evaluates content through a configured pipeline:

**loaders → preprocessors → SecurityGate (scanners → score aggregator → verdict)**

| Component | Responsibility |
| --- | --- |
| [Loaders](components/loaders/index.mdx) | Produce entries from configured input sources. |
| [Preprocessors](components/preprocessors/index.mdx) | Transform or derive entries before scanning. |
| [SecurityGate](gate.mdx) | Runs compatible scanners, applies their actions and severities, and returns a verdict for each entry. |
| [Scanners](components/scanners/index.mdx) | Inspect entry content and report a risk score, rationale, and optional match locations. |
| [Score aggregators](components/score-aggregators/index.mdx) | Combine the severity-weighted scores of blocking findings for the gate. |

See [Architecture](architecture.mdx) for the complete entry lifecycle and result
model.

Install the CLI and validate the repository's example configuration:

```bash
pip install "cerbia[cli]"
cerbia validate examples/cli-usage/config.cerbia.yaml
cerbia scan --config examples/cli-usage/config.cerbia.yaml --text "A short message"
```

`scan` needs configured loaders or at least one `--text` or `--file` argument.
It exits `0` for safe results, `1` for unsafe results, and `2` for configuration
or handled execution failures. A missing `--file` path currently yields no
entry, which can result in a safe empty scan.

Continue with [Configuration](configuration.mdx). [Packages](packages/index.mdx)
explains the optional ML, Presidio, and ProtectAI boundaries.
